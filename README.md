# Ruslan Savchuk — Astro

Портфоліо на Astro зі статичною збіркою. Дизайн, анімації та інтерактивні елементи перенесені з початкової HTML-версії. Сайт підтримує українську, англійську, французьку, іспанську, німецьку та португальську мови.

## Запуск

Потрібен Node.js 24 LTS (або сумісний Node.js від 22.23.4) та npm від 9.6.5. Якщо використовуєте nvm, виконайте `nvm use`: версію вказано в `.nvmrc`.

```sh
npm install
npm run dev
```

Відкрийте адресу, яку виведе Astro, зазвичай `http://localhost:4321`.

## Перевірка й публікація

```sh
npm run check
npm run build
npm run preview
```

`npm run build` створює готовий сайт у `dist/`. Для статичного хостингу задайте команду збірки `npm run build` і папку результату `dist`. Вміст `src/` не потрібно завантажувати як готовий сайт. Після зміни вихідних файлів повторіть збірку.

## Де редагувати

- `src/pages/index.astro` — порядок секцій головної сторінки.
- `src/layouts/SiteLayout.astro` — HTML-документ, метадані та підключення стилів і скриптів.
- `src/components/` — шапка, секції, футер і вікно опису проєкту.
- `src/components/BrandLogo.astro` — спільний логотип RS, ім’я та підпис професії в шапці й футері.
- `src/styles/styles.css` — початкові глобальні стилі, адаптивність і CSS-анімації.
- `src/styles/theme.css` — темна палітра. Порядок стилів задає `src/styles/global.css`.
- `src/data/config.js` — ім’я, назва, email і посилання на соціальні мережі.
- `src/data/projects.js` — додаткові роботи та переклади їхніх описів. Деталі — у `PROJECTS.md`.
- `src/scripts/app.js` — переклади, мови, меню, фільтри, проєкти та форма.
- `src/data/translations/es.js` — повний іспанський переклад інтерфейсу, повідомлень форми й описів концептів.
- `src/data/translations/de.js` — повний німецький переклад інтерфейсу, повідомлень форми й описів концептів.
- `src/data/translations/pt.js` — повний португальський переклад інтерфейсу, повідомлень форми й описів концептів; основний варіант — португальська Португалії.
- `src/scripts/motion.js` — анімації появи, рух ілюстрації та індикатор прокручування.
- `public/assets/` — оригінальні зображення, шрифти та favicon; доступні за адресами `/assets/...`.

Новий бренд RS використовує сині акценти на темному тлі. Оригінальне зображення, підготовлений знак і параметри його створення описані в `BRAND.md`.

Astro збирає клієнтський код з `src/scripts/client.js`: спочатку створюються проєкти та обробники, потім підключаються анімації. Налаштування й роботи імпортуються як JavaScript-модулі.

Під час відкриття головної сторінки мова визначається насамперед із `navigator.language`, потім із решти мов браузера. Підтримуються також регіональні варіанти: `uk-CA`, `uk-UA`, `es-ES`, `es-MX`, `de-DE`, `de-AT`, `de-CH`, `pt-PT`, `pt-BR`, `pt-AO` тощо. Якщо підтримуваної мови немає, відкривається англійська версія.

При кожному новому відкритті та перезавантаженні сайт знову визначає мову браузера. Ручний вибір у перемикачі діє лише для поточного перегляду: він не зберігається в localStorage і не додає `?lang` до адреси. Старі записи `devfolio-language` та `devfolio-language-preference-v2` видаляються, щоб раніше вибрана французька або інша мова не підміняла мову пристрою.

Посилання `?lang=uk`, `?lang=en`, `?lang=fr`, `?lang=es`, `?lang=de` або `?lang=pt` визначає мову для одного відкриття. Після застосування параметр `lang` прибирається з адреси; решта параметрів та якір зберігаються. Тому наступне перезавантаження чи повторне відкриття знову використовує мову браузера. Повернення зі збереженої сторінки через back/forward cache також відновлює автоматичний вибір. Подія `languagechange` та повернення до вкладки після зміни мови браузера оновлюють переклад без перезавантаження; звичайне перемикання вкладок не скидає поточний ручний вибір.

## SEO

Основна адреса сайту — `https://ruslansavchuk.com/`, задана в `src/data/config.js` та використана в Astro, canonical, Open Graph і структурованих даних JSON-LD (`Person` та `WebSite`). Sitemap і robots.txt генеруються під час збірки з `src/pages/sitemap.xml.ts` та `src/pages/robots.txt.ts`.

Sitemap містить одну канонічну сторінку: переклади зараз перемикаються JavaScript на тій самій сторінці, тому `?lang=…` не додані як окремі індексовані сторінки. Окремі мовні URL з HTML-перекладами та hreflang потребуватимуть додаткової реалізації.

Worker повертає `301` з `www.ruslansavchuk.com` на HTTPS-адресу без `www`, зберігаючи шлях і параметри. `run_worker_first: true` потрібен, щоб перенаправлення спрацьовувало також для головної сторінки й статичних ресурсів. Запити основного домену передаються до `ASSETS`, а `/api/contact` — до обробника форми.

Після публікації в Google Search Console відкрийте ресурс `ruslansavchuk.com` (або URL-prefix `https://ruslansavchuk.com/`), розділ **Sitemaps**, та надішліть `https://ruslansavchuk.com/sitemap.xml`. Сам факт публікації sitemap і його згадки в robots.txt не означає подання через Search Console або гарантованої індексації.

## Контактна форма

Кнопка «Відправити» надсилає заявку через `POST /api/contact` у Cloudflare Worker. Телефон необов’язковий: поле приймає довільний формат без маски. Ім’я, email, послуга й повідомлення перевіряються також на сервері.

Листи адресовані лише `ruslan.savchuk.dev.ca@gmail.com`, відправник — `website@forms.ruslansavchuk.com`. Email клієнта встановлюється у `Reply-To`, щоб відповісти йому безпосередньо. Текст листа підтримує українські символи й довільний текст телефону. Адресат заданий у `worker/contact.ts` і обмежений binding `CONTACT_EMAIL` у `wrangler.jsonc`; відвідувач не може його змінити.

У Cloudflare мають бути увімкнені Email Routing для `forms.ruslansavchuk.com` та підтверджена адреса одержувача. Поштові записи основного домену не потрібно замінювати. `wrangler.jsonc` додає email binding, обмеження 5 спроб за 60 секунд на IP у кожному розташуванні Cloudflare та запускає Worker перед видачею ресурсів для перенаправлення домену й обробки `/api/contact`. Приховане поле відсіює простих ботів. Дані клієнтів не записуються в логи.

Форма показує успіх лише після прийняття листа поштовим сервісом. Під час запиту повторне відправлення заблоковане. Якщо сталася помилка або втрачено мережу, введені дані залишаються у формі.

Локальна перевірка всього сайту разом із серверним обробником:

```sh
npm run build
npm run preview:worker
```

Wrangler виведе локальну адресу, зазвичай `http://localhost:8787`. У локальному режимі email binding імітує надсилання, реальний лист не відправляється. `npm run dev` і `npm run preview` запускають лише Astro та не містять серверного маршруту форми.

```sh
npm test
npm run check
npm run deploy:check
```

Остання команда перевіряє пакет Cloudflare без публікації. Після дозволеної публікації через GitHub автоматична команда `npx wrangler deploy` використає конфігурацію з репозиторію. Реальну доставку листа потрібно перевірити після розгортання.
