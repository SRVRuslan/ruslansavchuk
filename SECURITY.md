# Захист сайту

Сайт статичний; серверний маршрут — лише `POST /api/contact` у Cloudflare Worker. Облікових записів відвідувачів, паролів і бази даних у цьому проєкті немає.

## Заголовки та ресурси

- Astro генерує CSP з SHA-256-хешами дозволених скриптів і стилів. `build/security-headers.mjs` переносить її в HTTP-заголовок через згенерований `dist/_headers`; збірка зупиняється, якщо політики немає або вона перевищує ліміт Cloudflare. Довільні inline-скрипти, обробники подій, стилі в атрибутах та `eval` заборонені.
- Дозволені локальні ресурси, Turnstile, Cloudflare Analytics і зображення пов’язаного портфоліо фотографки. Додавання зовнішнього сервісу потребує перегляду CSP.
- Worker додає захист від вбудовування (`frame-ancestors 'none'`, `X-Frame-Options: DENY`), MIME-sniffing, обмеження referrer, доступу до камери/мікрофона/геолокації та ізоляцію відкритих вкладок. Заголовки застосовуються також до помилок API й перенаправлень.
- HSTS діє один рік для HTTPS-відповідей; `includeSubDomains` і preload не застосовуються без окремої перевірки всіх субдоменів.
- Альтернативні `workers.dev` і preview URL вимкнені. Worker також перевіряє hostname, перенаправляє HTTP/www на канонічний HTTPS-домен та дозволяє для статичних ресурсів лише GET/HEAD. Локальний Worker запускається з `--host localhost --local-protocol https`, щоб перевіряти CSP також у Safari/WebKit.

## Контактна форма

- Збіг Origin і Fetch Metadata, JSON Content-Type, обмеження тіла 32 КіБ та часу читання 5 секунд. Стиснені тіла не приймаються.
- Перевірки полів на сервері: ім’я до 100 символів, email до 254, повідомлення 10–5000, телефон — необов’язковий довільний текст до 100 символів. Отримувач/відправник фіксовані, текст листа передається як base64 plain text; користувацькі значення не стають HTML чи довільними поштовими заголовками.
- Приховане поле проти простих ботів; окремі ліміти на IP: 30 спроб/хв до читання JSON і 5 перевірок заявки/хв. Cloudflare Rate Limiting binding має локальні лічильники в кожній локації, а не глобальний ліміт на весь світ.
- Turnstile завантажується біля форми або при фокусі. Сервер вимагає токен і перевіряє `success === true`, точний hostname та `action === 'contact'` через Siteverify з тайм-аутом 8 секунд. Відсутній токен, збій сервісу чи відсутня конфігурація блокують доставку. Одноразовість токенів забезпечує Siteverify; клієнт скидає їх після кожної спроби.
- Production-віджет дозволяє лише `ruslansavchuk.com` і `www.ruslansavchuk.com`. Публічний sitekey зберігається в `src/data/config.js`; секрет — тільки в Cloudflare Worker secret `TURNSTILE_SECRET_KEY`. Секрет не додається до Git, HTML, JS, wrangler.jsonc чи логів. Локальний Astro dev використовує офіційний тестовий sitekey; production-збірка — справжній. У локальному Worker конфігурація без секрету навмисно не дозволяє надсилання; автоматичні тести замінюють Siteverify та доставку листів.
- Персональні дані та тексти заявок не записуються в логи. Помилка зберігає введені дані в поточній формі; локальне сховище для них не використовується.

## Підтримка

Після зміни коду: `npm run check`, `npm run build`, `npm test`, `npm audit`, `npm run deploy:check`. Тести також перевіряють CSP і відповідність хешів inline-ресурсам у готовій збірці, тому збірку потрібно створити перед тестами. Браузерна перевірка має використовувати production-збірку разом із Worker, оскільки Astro dev не застосовує production CSP. Не надсилайте реальні тестові заявки без потреби: використовуйте підміну Siteverify й email-сервісу.

GitHub Actions перевіряє зміни та щотижня виконує аудит залежностей; дозволи workflow — лише читання репозиторію, версії actions зафіксовані SHA. Dependabot налаштований для npm і GitHub Actions. Фактична доступність автоматичних запусків залежить від налаштувань GitHub-репозиторію.

Окремо власник має підтримувати двофакторну автентифікацію Cloudflare/GitHub, актуальні способи відновлення доступу й мінімальні права токенів. Ці налаштування облікових записів не змінюються кодом сайту. Захист не означає гарантію від усіх атак або проведення повного пентесту.
